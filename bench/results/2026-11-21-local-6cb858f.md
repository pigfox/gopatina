## Wall-clock ratios

| Case | GoPatina / Rust | Plain Go / Rust | GoPatina / Go |
| --- | --- | --- | --- |
| `fib` | 0.730 | 1.159 | 0.630 |
| `sieve` | 1.123 | 0.966 | 1.163 |
| `suffix-sum` | 1.010 | 1.020 | 0.990 |

**These numbers are noisy.** Each binary runs for a fraction of a second,
the harness times whole processes with `date`, and the machine was busy.
Across the two 2026-11-18 runs and this one, `fib`'s GoPatina / Rust ratio
was 0.890, 1.039 and 0.730 although its hot function compiles to the same
instructions as the hand-written Rust (below). The spread is larger than any
real difference, so these ratios cannot show whether GoPatina is identical
to, faster or slower than Rust. That needs many more runs with the noise
measured, on a quiet machine or with CPU performance counters (not available
on this workstation: `kernel.perf_event_paranoid` is 4).

## Machine code

Each case's generated crate (`gopatina build -emit-rust`) and hand-written
crate were compiled with the same rustc 1.93.0 and the same flags, and the
functions disassembled with `objdump -d` (addresses masked):

```sh
F="-C opt-level=3 -C codegen-units=1 -C overflow-checks=off -C debug-assertions=off --edition 2024"
rustc $F -o emit <emitted crate>/src/main.rs
rustc $F -o hand bench/cases/<case>/rust/src/main.rs
objdump -d --no-show-raw-insn -C emit   # and hand; compare main::<function>
```

| Case | Result |
| --- | --- |
| `fib` | `fib` is the same 30 instructions in both. |
| `suffix-sum` | `checksum` is inlined into `main` in both; the loop is the same. The generated `main` has 3 more instructions, the one-time call that installs GoPatina's Go-style panic hook at startup. |
| `sieve` | Different. `count_primes` is inlined into `main` in both. The generated inner loop does one extra bounds check per pass (two compares per pass instead of one) and uses signed compares, because Go's `int` becomes `i64` and the index is `j as usize`, where the hand-written Rust uses `usize` and the compiler proves the index in range. |

The `sieve` bounds check is the one known code-generation gap against
hand-written Rust in the suite. Closing it without changing Go's semantics
is the next compiler change.
